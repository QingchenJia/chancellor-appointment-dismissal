# 宋代宰执拜罢查询系统 UI 与交互升级设计

## 背景与目标

当前系统是 FastAPI 提供数据接口、原生 HTML/CSS/JavaScript 构建界面的单页检索工具。现有页面以深色金棕档案风格呈现，采用筛选、结果、详情三栏常驻布局。查询字段和业务链路已经满足基本需求，本次升级不改变数据库、数据模型、查询接口或核心功能，重点改善视觉层级、长时间阅读舒适度、结果扫描效率、状态反馈、键盘操作和桌面端空间利用率。

目标是将页面升级为浅色、现代、简约且保留适度文献气质的专业检索工作台。桌面端高效检索和长时间阅读是首要场景；平板及手机只保证页面可访问与基本操作，不作为完整体验优化目标。

## 设计原则

- 保留现有查询字段、快捷筛选、时间分布、表格分页和详情内容。
- 不修改现有 API 请求参数、响应结构和后端行为。
- 结果浏览是页面主任务，详情阅读按需展开，不常驻挤压结果区。
- 通过留白、排版、色彩和细分隔线建立层级，不依赖厚重渐变、描边或装饰纹理。
- 所有异步行为都有加载、成功、空结果或错误反馈。
- 鼠标和键盘均可完成核心检索与详情阅读流程。
- 动效短促、克制，并尊重系统的减少动态效果设置。

## 信息架构与布局

页面采用“顶部品牌栏 + 左侧筛选栏 + 主结果区”的两栏工作台结构。

### 顶部品牌栏

顶部栏压缩垂直高度，标题左对齐，保留“宋代宰执拜罢一览”主标题和简短数据说明。英文副标题不再占据主要视觉层级，可缩短或作为低对比度辅助信息。顶部栏不承载新的业务功能。

### 左侧筛选栏

筛选栏在桌面端保持固定宽度并独立滚动，避免页面高度不足时隐藏底部控件。现有字段按以下三组组织：

1. 人物与时间：人名、起始年、终止年、月份。
2. 朝代信息：皇帝、年号。
3. 事件内容：事件类型、原文关键词。

查询按钮是唯一高强调主操作。清空操作采用低优先级文字按钮。北宋、南宋、任命、罢免继续作为快捷筛选，但改为具有默认、悬停、键盘聚焦和选中状态的筛选胶囊。

### 主结果区

主结果区占据剩余空间，包含结果标题、记录总数、当前筛选摘要、精简时间分布、数据表格和底部分页。表格保留公元年月、皇帝、年号、人物、类型和原文摘要六列，不改变字段含义。

时间分布降为辅助概览，减少高度，避免压缩表格。分页固定在结果面板底部，显示当前页与总页数，并保留上一页、下一页操作。

### 详情侧滑面板

右侧常驻详情栏改为按需侧滑面板，桌面端宽度控制在 480–560px。点击结果行或使用键盘打开详情；面板关闭后保留结果行选中状态。遮罩保持低强度，使用户仍能感知结果上下文。

详情内容包含年月、皇帝、年号、人物、事件类型、源单元格、完整原文和批注。正文不再限制为八行，面板内容可独立滚动。面板提供清晰的关闭按钮，支持 Esc 关闭。

## 视觉体系

### 色彩

- 页面背景使用暖米白，降低纯白大面积显示造成的视觉疲劳。
- 内容面板使用白色或接近白色的暖色表面。
- 正文使用墨灰色，次要信息使用中性灰。
- 主要操作、焦点和选中状态使用低饱和黛青色。
- 任命、罢免、死亡等类型允许使用克制的语义色，但必须保持文字对比度。
- 错误使用低饱和红色，避免大面积高刺激色块。

### 字体与排版

主标题和少量章节标题保留宋体或衬线字体，建立文献气质；表单、表格、按钮和正文使用清晰的中文无衬线字体。结果表格采用适合连续扫描的紧凑行高，详情原文采用更宽松的行距。

### 形状与层级

面板和浮层使用 10–14px 圆角。层级主要通过背景色、留白和细分隔线表达，仅在侧滑面板、下拉菜单等浮层使用柔和阴影。移除现有厚重渐变、大面积金色边框和高亮文字阴影。

### 交互状态

输入框、按钮、筛选胶囊、表格行和侧栏操作均提供可识别的悬停、按下、禁用和 `:focus-visible` 状态。点击区域不小于常规桌面控件的舒适尺寸，颜色不作为传达选中或错误状态的唯一方式。

## 核心交互流程

### 初始化

页面初始化时并行请求筛选项、时间分布和首屏结果。各区域独立处理加载和失败状态：某个辅助请求失败不会阻止其他区域可用。筛选项或时间分布失败时显示区域级重试提示；首屏结果失败时在结果区显示错误说明和重试按钮。

### 查询与筛选

用户填写筛选条件后点击查询，或在文本与年份输入框中按 Enter 发起查询。查询开始时：

- 当前页重置为第一页。
- 查询按钮进入忙碌和禁用状态。
- 结果区显示轻量骨架屏或明确加载状态。
- 新请求获得递增标识；只有最后一次发起的查询可以更新页面，避免过期响应覆盖新结果。

快捷筛选点击后立即查询，并显示选中状态。结果区顶部将所有生效条件渲染为可移除的筛选标签；移除单个标签会清除对应字段并重新查询。清空筛选会重置所有字段、快捷条件、分页和筛选标签，然后重新查询。

### 结果浏览与分页

表格行支持鼠标点击，也可通过 Tab 聚焦后按 Enter 打开详情。当前选中行具有独立于悬停的视觉状态，并设置语义属性表明选中关系。上一页和下一页按钮根据边界禁用；分页信息同时显示当前页和总页数。

没有匹配记录时，表格区域改为完整空状态，说明当前筛选没有结果并提供一键清空筛选。请求失败时不伪装为空结果，而显示错误状态和重试入口。

### 详情阅读

选择记录后立即打开侧滑面板并显示加载状态，请求成功后渲染详情。详情请求失败时面板保持打开，显示错误说明与重试按钮。关闭面板不会清除结果行选中状态。打开后焦点进入面板，关闭后焦点返回触发该面板的结果行。

侧滑面板使用短时位移与透明度过渡。`prefers-reduced-motion: reduce` 生效时移除非必要过渡。

## 响应式策略

桌面端 1280px 及以上是主要验收范围。较窄桌面窗口下，筛选栏可折叠为可恢复的侧栏，结果表允许横向滚动，详情继续使用右侧滑出方式。手机端将主要区域纵向排列或使用筛选抽屉，保证查询、查看结果和阅读详情可用，但不要求达到桌面端同等的信息密度和效率。

任何尺寸下都不得出现无法滚动到的筛选项、被固定高度截断的详情内容或隐藏滚动条导致用户无法判断内容可滚动的情况。

## 代码边界

本次主要修改以下文件：

- `web/index.html`：调整语义结构，加入筛选分组、筛选摘要、状态容器和详情侧滑面板。
- `web/styles.css`：建立浅色视觉令牌、两栏布局、浮层、响应式规则、交互状态与减少动态效果规则。
- `web/app.js`：增加请求状态管理、过期请求保护、筛选标签、键盘操作、侧栏焦点管理、错误重试和新的渲染逻辑。

后端 Python 模块、数据库、数据导入流程和 API 合约不在修改范围内。如前端测试需要以浏览器或 DOM 环境运行，可增加最小测试配置与测试文件，但不引入生产运行时框架。

## 错误与边界处理

- 初始化的三个请求分别捕获错误，避免单点失败导致整页不可用。
- 查询失败时保留用户输入的筛选条件，允许原地重试。
- 详情失败时保留已选记录和侧栏上下文，允许原地重试。
- 快速连续查询只接受最后一次请求结果。
- 分页总数为零时显示第一页的空状态，分页按钮均禁用。
- 缺失的皇帝、年号、月份或批注使用统一的中性占位文案，不输出 `undefined` 或空白结构。
- 自定义下拉菜单支持 Escape 关闭，并保持原生选择控件所需的可访问语义或提供等价键盘行为。

## 测试与验收

### 自动化测试

- 现有 Python 测试必须继续通过，证明 API 与数据行为没有回归。
- 为前端可分离逻辑增加测试，覆盖查询参数生成、总页数计算、筛选标签移除和过期请求保护。
- 为页面结构增加测试，确认筛选分组、状态区域、详情对话框语义与关键控件存在。
- 对核心交互进行测试，覆盖 Enter 查询、表格行打开详情、Esc 关闭详情、焦点返回、加载状态、空状态与错误重试。

### 人工验收

- 在至少一个 1280px 以上桌面视口完成查询、快捷筛选、分页、打开详情、关闭详情和清空筛选流程。
- 检查筛选栏、表格和详情面板均可独立滚动且没有内容遮挡。
- 检查表格在窄桌面视口可横向滚动，筛选栏可以折叠和恢复。
- 使用键盘完成查询、选择结果、打开详情和关闭详情。
- 检查加载、空结果和请求错误均有明确、可恢复的反馈。
- 启用减少动态效果设置后确认核心操作不依赖动画完成。

## 非目标

- 不新增查询字段、数据分析视图、列排序、列配置或 CSV 导出能力。
- 不重构后端 API、数据库模型、数据导入或历史文本解析逻辑。
- 不引入前端框架、组件库或远程字体依赖。
- 不实现主题切换或深色主题。
- 不以完整移动端产品体验为本次验收目标。
